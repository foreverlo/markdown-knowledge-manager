## 选题背景与目标

学生和知识工作者需要持续记录课程笔记、项目资料与工作经验。随着笔记数量增加，资料容易分散，查找与关联变得困难，迁移和备份也需要明确规则。本项目拟开发本地优先的 Markdown 笔记工具，围绕“记录、查找、关联、保全”完成一套可离线使用的知识管理流程。

首版目标是让用户能够创建并编辑笔记、查看预览、通过标签与关键词定位内容、连接相关笔记，以及导入导出和备份恢复。笔记内容存储在用户本机，不依赖账号或在线服务。

## 目标用户与主要场景

| 用户 | 场景 |
| --- | --- |

## 首版功能范围

| 需求编号 | 功能 | 优先级 | 交付批次 |
| --- | --- | --- | --- |
| FR01 | 新建、重命名、删除至回收站与恢复笔记 | 高 | B1 |
| FR02 | Markdown 编辑、自动保存和保存失败保护 | 高 | B1 |
| FR03 | Markdown 预览，不执行输入内容中的脚本 | 高 | B1 |
| FR04 | 标签管理与多标签交集筛选 | 高 | B1 |
| FR05 | 标题和正文关键词检索，结果按修改时间排序 | 高 | B1 |
| FR06 | 基于稳定标识的内部链接与反向引用 | 高 | B1 |
| FR07 | UTF-8 Markdown 文件导入，逐文件展示结果 | 高 | B1 |
| FR08 | Markdown 单文件导出 | 高 | B1 |
| FR09 | 手动备份与本地自动备份 | 高 | B1 |
| FR10 | 校验后恢复完整备份，失败时保留原数据 | 高 | B1 |
| FR11 | 字号、布局、快捷键与备份目录设置 | 中 | B2 |
| FR12 | 回收站体验与操作反馈 | 中 | B2 |

B1为核心功能阶段，B2补齐体验与易用性验收；正式首版应包含两批内容。

保存反馈采用“未保存、保存中、已保存、保存失败”四种状态，同时提供文字与图标。搜索无结果、空工作区和空回收站均须给出下一步入口。错误提示说明原因、数据是否保留及恢复动作。

## 范围与质量目标

首版为 Windows 11 64位上的单机、单用户、单工作区桌面应用。编辑、检索、链接、导入导出和备份恢复均可离线完成。不纳入云同步、多人共同编辑、移动端、插件市场、AI问答、附件管理、OCR或PDF导出。

团队协作通过本仓库管理开发工作；软件本身仍面向单个用户，不增加多人协作功能。

以下数值是验收目标，实际达标情况须在实现后测试：

- 基线环境为至少4核处理器、8GB内存、SSD，起始可用磁盘至少1GiB。
- 在1000篇有效笔记、每篇正文不超过50KiB的测试库中，5次冷启动均不超过5秒；切换、标签筛选、预览及检索各组30次采样的95百分位耗时不超过1秒，按升序第29项判定。
- 有效笔记与回收站各最多1000篇；单篇正文最多1MiB，全部正文合计最多100MiB，按UTF-8字节数计量。超限操作保留原数据。
- 连续30分钟，每5秒采样一次全部应用进程私有工作集合计，采样峰值不超过512MiB。
- 成功保存的数据在重启后可读取；恢复前校验备份并保留恢复前副本，失败时不部分替换数据。
- 5名首次使用者（3名学生、2名知识工作者）在无操作协助下完成6项任务；阅读指南最多60秒，每人总时限900秒，至少4人通过全部步骤与时限。具体操作判据沿用已有需求分析文档。

## 仓库协作方式

- 使用 Issues 记录任务与缺陷，条目注明需求编号、负责人、交付批次和验收条件。
- 每项开发任务使用独立分支，通过 Pull request 汇入主分支，由另一名成员审查。
- 提交说明关联需求或任务编号；需求变更同步调整验收条件与开发计划。
- 实际测试后再填写执行结果；未执行的测试保持“未执行”。
